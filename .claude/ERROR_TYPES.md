## 유형 1: `\\n` 이스케이프 문자 파싱 오류

### 증상
- 문제 헤더(header)에 줄바꿈 없이 문제 전체가 한 줄로 표시됨
- 헤더에 `\n` 문자열이 그대로 보임 (예: `다음 중...\n① ...\n② ...`)
- 보기 항목이 박스(boxMode)로 구분되지 않고 전부 헤더에 포함됨

### 원인
- JS 데이터 파일(unit_XX.js)의 `stem` 필드에 `\\n`으로 줄바꿈 표시
- 파일에서 Read 시 `\\n`(백슬래시+n, 2글자)으로 저장되어 있으므로,
  JS 문자열로 읽으면 실제 개행 문자(`\n`, 1글자)가 아닌 그냥 `\n` 2글자
- `split('\n')`은 실제 개행만 분리 → 전체 stem이 한 줄로 처리됨

### 수정 방법
`index.html`의 stem을 `split('\n')` 하는 **모든 위치** 앞에 전처리 추가:
```javascript
stem.replace(/\\n/g, '\n').split('\n')
```

수정 위치 (4곳):
1. `parseBoxStem()` 함수 내 `lines=stem...split`
2. `parseStemHeader()` 함수 내 `lines=(stem||'')...split`
3. `mkCard()` 내 `stemLines=q.stem...split`
4. `Q_EXPS_BOX` 블록 내 `stemLs2=q.stem...split`

### 영향받은 문제 예시
- SA15, SA22 (보기 포함 문제에서 헤더에 전체 stem 표시)

## 유형 2: O_TYPE 누락 (정답/오답 레이블 반전 오류)

### 증상
- 정답 항목에 `✗ 오답(틀린 것)` 표시, 오답 항목에 `✓ 정답(올바른 것)` 표시
- 즉, 레이블이 반대로 렌더링됨
- "옳은 것은?" 유형 문제에서 발생

### 원인
`management_data.js`의 `O_TYPE Set`에 해당 문제 ID가 누락됨.

**O_TYPE 레이블 렌더링 로직:**
```javascript
isOtype
  ? (isAns ? '✓ 정답(올바른 것)' : '✗ 오답(틀린 것)')    // O_TYPE: 맞으면 "올바른 것"
  : (isAns ? '✗ 정답(잘못된 것)' : '✓ 오답(올바른 것)')   // 非O_TYPE: 맞으면 "잘못된 것"
```

- "옳은 것은?" 문제 → O_TYPE에 등록해야 함 → 정답 exps의 `ox: 'O'`
- "틀린 것은?" 문제 → O_TYPE 등록 **불필요** (비등록이 기본)

**판별 기준:** `exps[ans-1].ox === 'O'` 이면 O_TYPE에 등록

### 수정 방법
`management_data.js`의 `O_TYPE Set`에 해당 ID 추가

### 영향받은 단원 추가 수정 (2026-05-07 4차 — 패턴 전수 분석)
stem 패턴 기반 자동 분류기로 1677문제 전수 검증 결과:

**새로 정의된 유형 분류 기준:**

| 유형 | 예시 패턴 | O_TYPE 등록 |
|------|----------|------------|
| 옳은 것은? / 적절한 것은? | `설명으로 옳은 것은?` | ✅ 필요 |
| 해당하는 것은? | `구성요소에 해당하는 것은?` | ✅ 필요 |
| 모두 고른 것은? (**긍정형**) | `옳은 것을 모두 고른 것은?`, `해당하는 것을 모두 고른 것은?`, `장점을 모두 고른 것은?` | ✅ 필요 |
| 모두 고른 것은? (**부정형**) | `옳지 않은 것을 모두 고른 것은?`, `해당하지 않은 것을 모두 고른 것은?` | ❌ 불필요 |
| 다음에서 설명하는 것은? | 개념 맞히기 문제 | ✅ 필요 |
| 짝지어진 것은? (**본문 긍정형**) | `옳게 짝지어진`, `해당하는 것으로 짝지어진`, `올바르게 짝지어진` | ✅ 필요 |
| 짝지어진 것은? (**본문 부정형**) | `해당하지 않는 것으로 짝지어진`, `옳지 않게 짝지어진` | ❌ 불필요 |
| 옳지 않은 것은? / 적절하지 않은 것은? | `설명으로 옳지 않은 것은?` | ❌ 불필요 |
| 아닌 것은? / 해당하지 않는 것은? | `구성요소가 아닌 것은?` | ❌ 불필요 |
| 거리가 먼 것은? | `설명으로 가장 거리가 먼 것은?` | ❌ 불필요 |
| 관련이 없는 것은? | `관련이 없는 것은?` | ❌ 불필요 |
| 성격이 다른 하나는? | `그 성격이 다른 하나는?` (이질 항목 찾기) | ❌ 불필요 |
| 계산 문제 | `얼마인가?`, `몇 %인가?` | ❌ 해당없음 |

**⚠️ 주의: "짝지어진 것은?" 판단 규칙**
- "짝지어진 것은?" 자체는 O_TYPE 판단 기준이 아님
- **문장 본문에 포함된 수식어**가 판단 기준:
  - 본문에 "옳은/적절한/해당하는/올바른" → **O_TYPE 등록**
  - 본문에 "해당하지 않는/옳지 않은/적절하지 않은" → **O_TYPE 등록 불필요**
- 현재 데이터셋(14건) 전부 긍정형으로, 모두 O_TYPE 등록 상태

## 유형 3: O_TYPE 잘못 등록 (레이블 반전 오류의 역방향)

### 증상
- "아닌 것은?" / "틀린 것은?" 유형인데 O_TYPE에 등록됨
- 정답(아닌 것)이 `✓ 정답(올바른 것)`으로 표시되어야 할 게 `✓ 정답(올바른 것)`으로 잘못 나옴
- 오답(올바른 것들)이 `✓ 오답(올바른 것)` 대신 `✗ 오답(틀린 것)`으로 표시

### 원인
"아닌 것은?" 문제의 정답 exps는 `ox: 'X'`인데 O_TYPE에 등록되면 레이블이 반전됨

### 수정 방법
`management_data.js`의 `O_TYPE Set`에서 해당 ID 제거

### 영향받은 문제 예시 (2026-05-07 수정)
- RA04 ("기업 입장에서의 마케팅이 아닌 것은?" → O_TYPE에서 제거)
- RA05 (함께 제거)

## 유형 5: Q3_TYPE 누락 (보기 포함 문제가 boxMode로 잘못 렌더링)

### 증상
- ㄱ~ㅁ 보기가 stem에 있고 opts가 조합형(예: "ㄱ, ㄴ" / "ㄱ, ㄴ, ㄷ")인데
  boxMode 렌더링이 적용되어 opts 항목들이 이상하게 표시됨

### 원인
`management_data.js`의 `Q3_TYPE Set`에 해당 ID 누락.
boxMode 조건: `parseBoxStem(stem).items.length > 0 && !Q3_TYPE.has(id)`
→ Q3_TYPE에 없으면 boxMode 강제 적용

### 수정 방법
`management_data.js`의 `Q3_TYPE Set`에 해당 ID 추가

### 판별 기준
- stem에 `ㄱ.` `ㄴ.` 등의 한글 자모 항목이 있음
- opts가 `ㄱ, ㄴ` 같은 조합형 또는 순서형
- 즉, opts 자체가 보기 항목이 아닌 경우

### 영향받은 문제 예시 (2026-05-07 수정)
- SA16, YA01 추가

## 유형 6: UA04 보기 항목 exps 구조 오류 (boxMode + Q_EXPS_BOX 충돌)

### 증상
- boxMode로 렌더링되는 문제에서 각 항목(ㄱ~ㅁ)별 해설이 동일한 내용 4개 중복 표시

### 원인
exps가 보기 항목(5개)이 아닌 opts 항목(4개)에 맞게 작성됨.
보기 항목별로 개별 exps가 필요한데 동일한 해설 4개만 있었음.

### 수정 방법
exps를 보기 항목 수(5개)에 맞게, 각 항목별 개별 해설로 재작성

### 영향받은 문제 예시 (2026-05-07 수정)
- UA04: exps를 5개 항목별 해설로 재구성
  - ㄱ(X): 유형제품, ㄴ(X): 유형제품, ㄷ(X): 유형제품, ㄹ(O): 확장제품, ㅁ(O): 확장제품

## 유형 7: 워크트리 수정사항이 메인 폴더에 미반영 (렌더링 오류의 근본 원인)

### 증상
- 워크트리에서 수정·커밋·push까지 완료했으나, 실제 앱(메인 폴더)에는 반영이 안 됨
- 코드 로직·데이터·O_TYPE 등을 확인하면 모두 정상인데 사용자는 여전히 오류를 봄
- 워크트리 preview로는 정상 렌더링, 실제 폴더 열어보면 이상 렌더링

### 원인
Claude Code의 **git worktree** 방식으로 작업 시:
- 워크트리(`.../.claude/worktrees/XXX/`)에서 커밋하면 `origin/main`에는 반영됨
- 그러나 메인 프로젝트 폴더(`경영학 작업/`)는 별도 working tree라 자동 업데이트 안 됨
- 사용자가 메인 폴더의 파일을 직접 여는 경우 → 워크트리 변경사항을 못 봄

### 수정 방법
메인 폴더에서 `git pull` 또는 핵심 파일을 워크트리에서 복사:
```bash
# 방법 1: git pull (로컬 미커밋 변경사항 없을 때)
cd [메인폴더]
git pull origin main

# 방법 2: 핵심 파일 직접 복사 (로컬 변경사항 보존 필요 시)
# management_data.js, index.html → 워크트리에서 복사
# data/unit_XX.js → 로컬 개선사항 병합 후 수정
```

### 충돌(conflict) 발생 시
- `management_data.js`: origin/main 버전이 로컬보다 항상 상위집합 → origin 버전 채택
- `data/unit_XX.js`: 로컬에 개선된 exps 텍스트가 있을 수 있음 → 내용 확인 후 병합
- 이후 `git add`, `git rebase --continue` 또는 `git push` 진행

### 재발 방지
- 워크트리에서 수정 완료 후 항상 메인 폴더도 `git pull` 확인
- 또는 메인 폴더에서 직접 작업하여 worktree/main 이원화 방지

### 영향받은 문제 예시 (2026-05-07 수정)
- TA04, TA05, TA09, TA11, TA16, TA17, TA18, TA23, TA27, TA45
  - 워크트리에는 O_TYPE 등록됨, 메인 폴더 management_data.js에만 미반영
  - `management_data.js` 복사 + `index.html` 복사 + `unit_RA.js` exps_ox 병합 수정으로 해결
